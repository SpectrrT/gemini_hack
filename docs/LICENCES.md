# Licences and redistribution

Checked 2026-11-21. Not legal advice; it is a reading of what the sources state.

## Short answer

The CaptainCook4D dataset states a permissive licence (Apache 2.0 on its own pages), so the **labels**
(`fixtures/tomato/labels.json`) and the **recorded answers** may be redistributed with attribution.
The **keyframes** are single frames cut from participants' videos. No page we found says in words that the
licence covers the videos, and the licence texts talk about "Software", not data. So redistribution of the
keyframes is *likely* fine but **not clearly stated**. Decision for the owner (see "If you want zero risk").

## CaptainCook4D

| What | Finding | Source |
|---|---|---|
| Project page, "License & Consent" | "Our dataset is licensed under the Apache License 2.0" | <https://aria-research-lab.github.io/projects/CaptainCook4D> |
| Annotations repo README, same heading | Same Apache 2.0 sentence | <https://github.com/CaptainCook4D/annotations> |
| Annotations repo `LICENSE` file and GitHub sidebar | **MIT**, "Copyright (c) 2023 Error-Dataset" (conflicts with the README) | <https://github.com/CaptainCook4D/annotations/blob/main/LICENSE> |
| Paper appendix | Reproduces an Apache 2.0 header, "Copyright [2023] The University of Texas at Dallas" | <https://arxiv.org/abs/2312.14556> |
| Consent | IRB approval (University of Florida) and written participant consent are linked from the project page; no redistribution terms are stated there | project page above |

What this means:

- Both stated licences (Apache 2.0, MIT) allow copying and redistribution with attribution and the licence
  notice. Neither is non-commercial or no-derivatives. The conflict between the two does not change that.
- Neither the project page nor the repo says which assets (videos, annotations, or both) the licence covers.
  Videos are hosted separately by the dataset authors; we did not find hosting terms.
- Our fixtures are derivatives: step names and times from the annotations, model answers recorded by us, and
  frames cut from the videos 12_17, 12_10, 12_43 (and the line-art panels the image model drew from them).
- Apache 2.0 asks for: a copy of the licence, a statement of changes, and keeping the copyright notice. Do this
  by adding the attribution paragraph below to the README (proposed text in `docs/SUBMISSION.md`).

Attribution text to use:

> Fixtures under `fixtures/tomato/` are derived from the CaptainCook4D dataset (Peddi et al., NeurIPS 2024
> Datasets and Benchmarks, <https://aria-research-lab.github.io/projects/CaptainCook4D>), licensed under the
> Apache License 2.0 per the dataset's project page. We use step labels and a small number of video frames,
> and recorded model answers. Modified from the originals.

### If you want zero risk

Only the keyframes carry real footage of people. Everything else is labels, our own recorded answers, or
generated line art. To remove the footage and keep the rest:

```
git rm -r fixtures/tomato/keyframes/          # 12 files: A_kf1.jpg ... A_kf12.jpg
```

(`sheet_as_sent.jpg` was inspected: it is the nine-panel line-art sheet, no real footage, so it can stay.)

Effect, tested in a scratch copy of commit 5395083 with the keyframes deleted:

- `scripts/import_tomato_fixture.py` **fails** with `TapeMiss: teach/tomato/keyframe/s01` (the card cannot be
  rebuilt, and the `cards/tomato/` card is never created).
- Therefore the five tests in `tests/test_replay_tomato.py` **skip** (their `skipif` checks
  `cards/tomato/card.json`): `test_card_has_the_nine_panels_that_were_tested` and the four replay-number tests.
  The other tests are unaffected (26 passed, 5 skipped, same 6 pre-existing failures as before the change).
- The README's "Run it (no key needed)" flow breaks at step 2. Fixing that needs a code change in
  `scripts/import_tomato_fixture.py` / `wordless/teach.py` (store the line-art panels without needing the frame),
  which is outside this task. Do not remove the keyframes without that fix unless you accept the demo's Teach
  replay being unavailable.

The line-art panels (`fixtures/tomato/panels/`) are images generated by the image model from the frames; they
show no faces or text but are still derivatives of the dataset, so the attribution applies to them too.

Not in the repo, and must stay out: the CaptainCook4D `.mp4` recordings (`data/` is git-ignored).

Notes:

- `imageio-ffmpeg` downloads/bundles an FFmpeg executable at install time. FFmpeg's builds are LGPL or GPL
  depending on configuration. We do not commit or ship the binary, only depend on the package, so nothing in
  the repo is affected. Do not add the binary to the repo.
- No other runtime dependencies are listed in `requirements.txt`; the Gemini API is called over plain HTTP
  from `wordless/gemini.py` without an SDK.
- The Gemini API and its outputs are governed by Google's terms; the recorded answers under `fixtures/` are
  outputs of that API. No credentials are in the tree or history (see the audit in `docs/SUBMISSION.md`).
- The repo has **no licence for our own code yet**. Proposed: add an MIT `LICENSE` (owner's call; nothing here
  does it because it is outside the files this task may edit).
